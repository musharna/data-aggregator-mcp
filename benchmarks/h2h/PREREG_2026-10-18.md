# Pre-registration, 2026-10-18: head-to-head rounds 4 and 5

Committed before any round-4 or round-5 run. Anything run after a round's sweep, other
than the adjudication and analysis below, is exploratory and labelled so.

## Shared

- Driver [`run.py`](run.py), scorer, validity rule, leak scan and oracle as in
  [`README.md`](README.md#controls). Model `claude-opus-5-5`, Claude Code 2.1.302 (the
  version is recorded per row), `--setting-sources ""`, one system prompt, a fresh
  `/tmp` directory per run, $6 budget cap, 15-minute timeout, `--workers 1`.
- Every sweep runs as `flock <shared sweep lock> env HEAVY_RUN_MEM=6G heavy-run python3
  benchmarks/h2h/run.py ...`, with run directories under
  `~/data-aggregator-mcp-artifacts/h2h/`, after checking at least 5 GB free on `/`.
- Usage gate (added to `run.py` today, before any run): a sweep starts only when a fresh
  reading shows five-hour utilization below 0.50 and seven-day below 0.80. A run whose
  transcript shows five-hour >= 0.85 or a `rejected` status holds later runs until that
  window resets; each pause goes to `pauses.jsonl`. Seven-day >= 0.80 stops the sweep,
  and the stop is reported. **A row that the rate limit rejected before the model
  answered is a harness failure, not a result: it is re-run once** (automatically; the
  first attempt is kept under `_ratelimited/`). A second such failure stays as the row
  and scores invalid (recall 0).
- Job order: rep 1 of every task and arm, then rep 2, then rep 3; within a rep, task by
  task, arms dam, tu, web, bare. So each task's arms run back to back.
- Primary endpoint: each task's mean recall over its 3 runs after blind adjudication,
  an invalid run scoring 0. Primary comparison: dam vs web. Intervals: percentile
  bootstrap 95% over tasks, 10,000 draws, seed 0 (`analyze.interval`).
- Adjudication: the pooled unkeyed entries (`pool.json`, no arm attached, shuffled) are
  judged by one agent per round that built no key and ran no arm: a fresh headless
  `claude -p` session with no MCP server (so neither server under test), given only
  `pool.json`, the keys' prompts and criteria, and the archives' own APIs. One verdict
  per entry (alias of a keyed study, `add`, `optional`, `reject`) with a reason, into
  `adjudication.json` and `adjudication_reasons.yaml`; then everything is re-scored
  with `--adjudication`.
- Analysis: `analyze.py` (sets `r4`, `r5`) writes `summary.tsv` and `comparisons.tsv`:
  per-arm mean recall, valid-only recall, precision, median cost, wall time and tool
  calls with intervals; paired per-task differences with wins, losses, ties, the exact
  sign test and the bootstrap interval; the model-free baselines.

## Round 5 (new)

- Tasks V1 to V10, topics and backups fixed in [`round5/README.md`](round5/README.md)
  before any key. A backup is used only when the primary fails the size gate (5 to 30
  firm studies in at least 3 archives), and the key says so.
- Keys: one builder per task, at most 2 at a time, each a fresh headless `claude -p`
  session with `--strict-mcp-config` and no MCP server, tools Bash, Read and Write only,
  told to use only the archives' own APIs, DataCite and Europe PMC, and to read nothing
  of this repository or any server's code. Each builder's transcript is scanned
  afterwards for any MCP call and for any path under this repository or its artifacts
  other than its own work directory; a hit voids that key, which is rebuilt. Keys and
  `tasks.json` live under `~/data-aggregator-mcp-artifacts/h2h/round5/` until the sweep
  ends; their sha256 values are committed before the sweep and the files after it. The
  oracle (key 100%, wrong list 0%) must pass before the sweep.
- Arms `dam,tu,web,bare`; 3 reps; 120 runs. dam = commit `0e3661f19db63480ad08656e506416fc9bd8b466`
  (0.75.1 plus the tool-description prefix note, unreleased):
  `--server-spec git+https://github.com/musharna/data-aggregator-mcp@0e3661f19db63480ad08656e506416fc9bd8b466`;
  tu = `tooluniverse==1.5.7` (the latest PyPI release today); `--exclude-newer
  2026-10-17T00:00:00Z` for every dependency.
- **Rule: dam better if dam's task mean is above web's on at least 8 of 10 tasks (sign
  test; ties count against dam) AND the bootstrap 95% interval of the mean per-task
  recall difference (dam - web) is above 0.** dam worse: the mirror image. Otherwise
  "not separated". The valid-only verdict must agree, or the verdict is "not separated".
  This is a decision rule: 8 of 10 has exact sign-test p = 0.055 one-sided (0.109
  two-sided), 9 of 10 p = 0.011 one-sided. Secondary, reported with the same rule but
  not part of the verdict: dam vs tu, each arm vs bare; also precision, cost, wall time
  and tool calls with intervals, and the model-free baselines.
- Win (the 10-18 benchmark ledger): "dam better" on round 5 is a win; "not separated" is
  a tie; "dam worse" is a loss. A pooled 15-task view of rounds 4 and 5 is reported as
  exploratory only.
- Mechanism readout: how many dam runs met a bare-name refusal ("No such tool
  available") in rounds 4 and 5; the fix is tested only if round 4 (0.74.0, no note)
  shows some and round 5 shows fewer.
- DataCite baseline queries, written before any fetch (primary / backup): V1 "spatial
  transcriptomics cochlea" / "spatial transcriptomics placenta"; V2 "cnidarian ATAC-seq"
  / "sponge ATAC-seq"; V3 "stuttering MRI" / "blind MRI"; V4 "wind turbine bird bat
  fatalities" / "bird window collisions"; V5 "human milk metabolomics" / "honey
  metabolomics"; V6 "ice core black carbon" / "ice core methanesulfonic acid"; V7 "whale
  aerial imagery detection" / "seal aerial imagery detection"; V8 "Parkinson speech
  recordings" / "dysarthria speech recordings"; V9 "hospital sink drain microbiome" /
  "dishwasher microbiome"; V10 "dental calculus ancient DNA animal" / "coprolite ancient
  DNA".
- Cost estimate: 120 runs at the round-4 rates, about $100 to $155, plus key builders
  and the adjudicator.
