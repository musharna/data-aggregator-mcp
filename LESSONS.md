# Lessons

One line per miss: date, the class of miss, and the mechanism that now catches it.

- 2026-09-16 — A live-network test's fixed timeout (90 s) was below the code's own retry budget (3 x 30 s + backoff), so an upstream outage became `TimeoutExpired` (fail) instead of exit != 0 (skip); and the CLI dropped the router's per-source `errors`, so `[]` + exit 0 passed the test vacuously. Now: timeout derived from the retry constants (`_zenodo_retry_budget_s`), CLI names failed sources on stderr and exits 1 when all failed, and the live test asserts the requested count.
- 2026-09-16 — A registry table that stores function objects at import (`_RESOLVERS`) defeats `monkeypatch.setattr` on the module; three tests silently hit live NCBI from required CI and one passed for the wrong reason. Now: resolvers are call-time thunks, a binding test guards it, and `unshare -rn sh -c 'ip link set lo up; pytest'` is the offline control that exposes any live dependency in the suite.
- 2026-09-22 — Paging tests asserted one or two pages, never the whole walk. So omics and literature sharing one offset across sub-databases (60/90 records lost), semantic/multi-query window consumption, and DOI-dedup offset drift all shipped green. Now: `tests/test_router_paging.py` walks every cursor to the end and asserts the union equals the upstream set, with no duplicates. Offsets are counted in each stream's own upstream order, in one place (`router._fetch_page`).
- 2026-09-22 — Upstream failure became an empty success in many adapters (`not_found_returns=` on search endpoints, `isinstance(...) else []`, NCBI's in-200 `ERROR` envelope, `fetch` writing zero files). Each looked locally reasonable. Now: `_http.request_json(expect=, check=)` classifies wrong-shape and in-band-error bodies once, composite sources report each failed sub-database by name, and `fetch_files` raises when nothing was written.
- 2026-09-22 — `test_all_tool_outputs_validate_against_schemas` built the models and never read a schema, so it could not fail. Now it drives every tool's real handler and validates against the declared `outputSchema`, with a set-equality check so a new tool cannot escape it; a planted `required` field was seen to fail it.
- 2026-09-25 — The `fetch` tool description listed its fetchable sources by hand and drifted: four wired sources (UniProt, BioStudies, GBIF, data.gov) were missing and it ended "Verifies checksums" although most sources publish none. Now: `test_fetch_description_names_every_fetchable_source` fails on any fetchable prefix the description does not name (seen to fail on the old text), and the description says which sources are unverified.
- 2026-09-27 — File manifests read only the first page or the top level (OSF folders, Dryad and PRIDE pages, the OpenNeuro tree, BioStudies file lists) and their tests used one-page or flat fixtures, so truncation shipped green. Now: each walk's test serves the whole tree or every page and asserts the union equals the full fixture, next to a flat-deposit control, and each walk raises when it ends short of the upstream total or trips its guard.
- 2026-09-27 — Identity checks that could not fail: an accession search (a match) was used as an identity lookup (`geo:GSM…` became its parent series), and a Figshare version check stripped the version on both sides. Now: resolve keeps only the candidate whose own id equals the input, versioned DOIs hit `/versions/N`, and live tests resolve GSM/GPL/GDS ids and a `.v1` DOI.
- 2026-09-27 — A link to an older version was read as proof of being the latest, and `relate`'s version detector keyed on a field no Zenodo path filled, so it could never fire. Now: links can only prove "superseded", "latest" comes from the source that owns the version set (Zenodo `is_last`), and a test runs the adapter's own resolve output through `relate.detect`.
- 2026-09-27 — The PDB adapter put the paper's DOI in the record's `doi`, so DOI dedup folded sibling structures; moving it to `described_in` then silently dropped the retraction check that read `doi`. Now: `doi` identifies the record itself, a test dedups two siblings sharing a paper, and a test retracts only the paper of a PDB-shaped record.
- 2026-09-27 — Two upstream-facing declarations failed open: `boolean_query` defaulted to "yes" for sources whose parsers reject boolean syntax (GWAS, DANDI returned 0), and a Scholix deny-list named a target type (`literature`) that v3 never emits. Now: every source's `boolean_query` is live-probed against its upstream and a new source must add a probe query; Scholix keeps an allow-list of data types.
- 2026-09-27 — A record's fields disagreed with the bytes or the index they came from: a Dataverse `.tab` listed with the original upload's md5, a GBIF search hit read a field only the record endpoint has, a deleted UniProt entry returned 200 with a tombstone. Now: live tests hash the bytes at a listed URL, assert search hits carry a year, and resolve a deleted UniProt entry.
- 2026-09-27 — data.gov retired its CKAN API and a live test kept calling a handler's mcp 1.x signature; only the live-gated tests could see either and nothing ran them. Now: `nightly-live.yml` runs the suite with live tests every night and keeps one `live-upstream` issue open while it is red, and unit fixtures are trimmed captures of real responses.
- 2026-09-27 — A sandbox built as a denylist of named DuckDB filesystems (Local, HTTP) missed the others httpfs registers (S3/R2/GCS, HuggingFace), so `operate` SQL still read remote buckets and reached any host through `s3_endpoint`; the SSRF test covered only the one scheme the fix was written for. Now: all external access is switched off (`enable_external_access=false`) after the eager load, and `test_user_sql_cannot_reach_the_network_via_any_remote_filesystem` steers every S3-family scheme at a local listener and asserts nothing is requested, with `hf://` asserted separately.
- 2026-09-27 — An open JSON-Schema object accepted what the tool does not declare: `search(limit=3)` dropped `limit` and returned 10 hits with no error. Now: every tool input schema is closed (`additionalProperties: false`), and a test drives each tool in the tool table (set equality) with an undeclared argument, next to a declared-only control.
- 2026-09-27 — One question had two answers that drifted: fetch's gate refused Dryad and NASA CMR, while `access_modes` ("has a URL") and `operate` (reads the URL) said yes. Now: `fetch_gate.refusal` is the one predicate fetch, operate and `access_modes` ask, and a test resolves refused-shaped records next to a fetchable control.
- 2026-09-27 — Filters applied after fetch to a single window made `total` and an empty page lie ("soil moisture" 2019–2020: 0 of 127,525), and the first pushdown sent `()` for a blank query (DataCite HTTP 400). Now: Zenodo and DataCite evaluate the filters upstream, with a live test that the kind clauses partition the upstream total and a blank-query test; post-filtered sources report `errors["filters"]`.
- 2026-09-27 — Manifest fields were asserted against fixtures, never against what the source serves: every PDB entry listed a `.pdb` (404 for 4V6X), and DANDI and MetaboLights files carried no checksum although both publish sha256. Now: live tests HEAD every listed PDB URL and hash the bytes each DANDI/MetaboLights URL serves against the listed checksum.
- 2026-09-27 — A fail-soft enrichment plus a cache turned a transient failure into a durable, invisible one: a taxonomy 429 during resolve was logged server-side and the taxa-less record cached for the TTL. Now: the record names the failed step in `errors`, a record with errors is not cached, and a test resolves through a 429 then heals.
- 2026-09-28 — The 2026-09-27 fix for a failed enrichment being cached covered one consumer (taxonomy), not the pattern: the Zenodo latest-version, ScholeXplorer and doi.org agency lookups still returned a degraded value that is also a legal answer (None, `[]`, a bare DOI), so the resolve cache kept serving it. Now: each writes its failure to `errors`, and a test resolves twice and asserts the second call refetches, next to a clean record that is cached. Same class, still open: `idconv` and `fulltext`.
- 2026-09-28 — A default that belongs to the domain turns "unknown" into a claim: an unmapped resource type became kind `dataset`, and `rightsList[0]` was read as the licence when three publishers list an access status first. Now: unmapped types are `other`, a live test checks the four kinds' upstream counts add up to the unfiltered total, and the rights fixtures copy the live Harvard Dataverse, DataverseNO and Mendeley shape.
- 2026-09-28 — Flattening a multi-part API answer assumed its parts were disjoint: NCBI's two bioproject→sra link sets hold the same runs, so every run was listed twice. Now: `elink` returns the union, a test feeds it overlapping link sets, and the live check asserts the links are unique.
- 2026-09-28 — A fresh worktree without the dev extras ran `uv run pytest` through miniconda's pytest and site-packages, so the first "seen to fail" run exercised an installed copy, not the edited source. Now: run `uv sync --extra dev --extra operate` (the CI form) before the first test in a new worktree, and check that `uv run which pytest` resolves into `.venv`.
- 2026-09-28 — The "same class, still open" list was written from the files being edited, not from a sweep, so it named 2 of 4 members: the PubMed abstract and Hugging Face datasets-server catch-alls also turned a failure into a legal-looking "none" that was cached. Now: all four record the failure in `errors`, each has a resolve-twice test next to a cached clean record, and an open class is listed only after grepping its marker (`# noqa: BLE001`) across `src/`. Not a hook: "this fallback value is also a valid answer" is not visible in the syntax.
- 2026-09-29 — An upstream API retirement was announced (GWAS Catalog v1, supported until May 2026) and the adapter kept calling v1 for four months: the offline tests mocked hand-written v1 shapes (one with a wrong PMID), so they could not see the API change, and the live failure surfaced as "rate limited" (v1 answers 429 to everything). Now: the nightly live suite fails loudly and opens the `live-upstream` issue, the GWAS fixtures are verbatim captured responses, and a live test checks the trait-search semantics the source description promises. Not a hook: nothing in the repo can see an upstream deprecation notice.
- 2026-09-29 — A test that drives a retried failure slept through the real backoff (~3 s; review finding on #127), and nothing flags it because the suite has no per-test time budget. `pytest --durations` shows the class: ~9 offline tests at ~3.0 s each (idconv, fulltext, scholix, llm, citation, dataone, server, router, gwas), ~27 s of a 130 s run. Now: the flagged test stubs `_http.asyncio.sleep` like its neighbours. Still open, not a hook yet: an autouse fixture that makes `_http`'s backoff instant for every offline test.
- 2026-09-28 — A fuzzing finding (#85) sat open for two weeks and named one parse site of four: record URLs, which uploaders control, went through `urlsplit`/`urlparse` in the egress guard, in the `operate` and `fetch` scheme checks (which run before the guard), and in Dataverse's landing-URL base, and each let the stdlib's bare `ValueError` escape. Now: `egress.split_url` is the one parser for a record URL and raises `ValidationError` naming the file and the URL; a Hypothesis run of 4,000 URLs finds no bare exception, and the same harness on the old code finds the crash at once. Not a hook yet: "every `urlsplit` of an untrusted URL handles `ValueError`" needs to know which URLs are untrusted.
- 2026-09-28 — The GWAS v2 port measured that 11 of 20 requests took longer than the 30 s timeout and answered it with retries, but a retry under a timeout shorter than the upstream's usual reply time is cut at the same point every time: replies at 31-33 s never landed, and the live trait search failed "unreachable after 3 tries" the same evening. Now: a unit test fails if any GWAS request (search, study, publication) waits less than the slowest successful reply measured (32.7 s), and the timeout is 60 s. Not a hook: whether a timeout is too short depends on the upstream's measured latency, which only a live probe sees.
- 2026-09-29 — The DataCite adapter never asked for an order, and DataCite's default is most recently updated first, so its "search" was a feed of recent edits that the router interleaved as relevance; it surfaced only as a flaky live pagination test (records edited mid-run reappeared on page 2), and an early reading blamed index churn and proposed pinning the test to old publication years, which would not have held (old records are re-edited every few minutes). Now: a unit test fails if any DataCite search request lacks `sort=relevance`, a live test fails if the results match DataCite's recency page instead of its relevance page, and the live pagination test traces a repeat to the router or to the upstream instead of a bare `assert False`. Not a hook: which sort an upstream applies by default is only visible in a live response.
- 2026-09-29 — A test written to attribute a failure to one of two causes used a predicate both causes satisfy (review finding on #134): a repeated record whose page-1 position the cursor had marked "ahead" was classed as an upstream move, yet a router ignoring its own ahead list leaves the same trace, so the router bug would have been retried and reported as the upstream's. Now: the classifier is a function with an offline test holding one case per cause, including the router-ignored-ahead case the old predicate called "upstream". Not a hook: whether a predicate discriminates depends on the causes it is meant to separate.
- 2026-09-29 — The 0.54.0 release PR said its `uv.lock` bump "moves pyjwt only" after checking the diff with `grep '^[+-](name|version) '`, a pattern that cannot match the indented `{ name = ... }` dependency-edge lines, so four new resolver markers on httpcore2's and uvicorn's edges were invisible to the check that vouched for their absence (review finding on #135). Now: a lock diff is described from every changed line (`git diff -- uv.lock | grep '^[-+]'`), and the PR names the marker churn. Not a hook: whether a filter can see what a claim is about depends on the claim.
- 2026-09-29 — A live test asserted a property of the day's upstream data rather than of our code: `test_live_relate_emits_real_hint` related the top omics results for "RNA-seq" and required two of them to share a study, which depends on what NCBI received most recently, so it failed on a day `relate` was working (8 results, 8 studies). Now: the test builds its input from live lookups that guarantee the property (a run, its study accession, a sibling run from searching that accession, and a run from another study as a control), and asserts the exact hint. Not a hook: whether a live test's premise is guaranteed or incidental depends on the upstream's semantics.
- 2026-09-29 — A live test built to blame one component fed it an input it had not checked (review finding on #136): the sibling run came from a text search on the study accession and was never confirmed to carry that study, so a search returning an unrelated run would have failed the test as a `relate` bug. Now: every input the test hands `relate` has its study read from its own resolved record, and an injected unrelated run is skipped, not paired. Not a hook: which inputs a test takes on trust depends on what it means to blame.
- 2026-09-29 — A security guard encoded the attack shapes it was written against instead of the grammar they come from (nightly mutation finding, #88): the userinfo check rejected `host@` and `host:<digits>@`, so any other password (`creativecommons.org:x9@evil.com/licenses/by/4.0/`) passed and was checked ALLOW CC-BY-4.0. It surfaced only because a mutant shifting the digit scan by one survived. Now: the check implements RFC 3986's rule (an `@` anywhere before the authority ends makes the token userinfo), fails closed past the scan cap, and a test holds a password of each kind plus one longer than the cap. Not a hook: whether a check follows the grammar or a list of cases is read from the spec, not the code.
- 2026-09-29 — License tests asserted substrings (`"non-commercial" in reason`, `"same-license" in reason or …`) where the exact value is the contract, so 84 mutants that garbled a join, dropped a label, or appended a stray suffix survived (#88). Now: every verdict branch has an exact-reason test, and mutmut on `license_compat` reports 466 killed, 0 survived. Not a hook: which assertions should be exact depends on what callers read.
- 2026-09-29 — A test compared a function's output with a table the same function had filled (review finding on #137): `_pre_4_0_cc_profiles()` against the `LICENSE_MATRIX` it populates at import, so every edit changed both sides and passed. It killed the mutants only because mutmut switches a mutant on after import, which made a tautology look like coverage. Now: the builder is compared with independently written values (the hand-written 4.0 profiles, literal ids), and an injected wrong shape fails it. Not a hook: whether two sides of an assertion share a source is a property of the data flow.
- 2026-09-30 — The router's tests checked what page 2 returned but never what page 2 handed on, and their fake upstreams ignored every argument they did not assert on (#88: 347 surviving mutants in `router`). A continuation that dropped `organism`, `rank`, `collapse_mirrors`, the multi-query `ahead` or `pd` while reading the cursor, or an upstream called with `client=None`, still passed: the damage shows only on page 3 or in a transport setting no fake looked at. Now: `tests/test_router_observed.py` decodes page 2's own cursor and compares its settings to page 1's, and a recording fake asserts the caller's client object reaches every upstream call. Not a hook: which argument a fake may ignore depends on what the code under test does with it; the nightly mutation run is the check.
- 2026-09-30 — A loop that retried until a clash cleared was tested only with clashes its retry could clear (#88 mutation burn-down): `_plan_paths` renamed a path's file to escape a collision, and its tests covered two files with one name and a file landing where a directory was, but never a directory landing where a file was, which the rename cannot reach, so a record listing `Data` then `data/x.csv` hung the server. The surviving mutants in the clash predicate pointed at it; no mutant produced the hang itself. Now: paths are placed one component at a time, renaming the component that clashes, and `test_a_path_through_a_planned_file_gets_its_own_directory_instead_of_hanging` runs under a 5 s alarm. Not a hook: whether a retry can reach its exit condition depends on what the retry changes.
- 2026-09-30 — An entry point was tested only by launching it (#88: 272 surviving mutants in `server`, 103 of them in `_run_serve_cli`): the HTTP serve tests start a real server process, which proves it starts and refuses a spoofed Host, but runs outside the in-process mutation run and never checks which flag reaches which `serve_http` argument, so `--allow-host` keeping only its last value, `--stateless` dropped, or a help line garbled all passed. Now: `tests/test_server_observed.py` calls `main([...])` in-process with a recording `serve_http` and pins every flag, default, the refusal exit code and `--help`, while the subprocess tests stay as the real-execution check. Not a hook: whether a subprocess test observes a given branch depends on what it asserts, not on the fact that it spawns.
- 2026-09-30 — A normaliser was tested for presence, not value (#88: 166 surviving mutants in `biostudies`): its tests asserted `r.title`, `any(link.rel == "described_in" ...)`, `len(r.files) > 10` and `pytest.raises(NotFoundError)`, so a reversed title fallback, a dropped description or `access`, a PMID taken from a non-PMID attribute, a duplicate file ending the file walk, a retry budget of 3 instead of 2, and error text naming no BioStudies call all passed, and nothing showed that a file list answering an error envelope raises rather than silently shortening the manifest. Now: `tests/test_biostudies_observed.py` compares whole records against the real fixtures, parametrises every DOI/PMID rule, and pins each call site's request, retry count and exact error text. Not a hook: whether an assertion checks a field's value or only that it is set depends on the field.
- 2026-09-30 — A mock that answered every path the code might ask for could not tell which one it asked (#88: 148 surviving mutants in `dandi`): the resolve tests' server matched `/info/` and `/assets/` by suffix, whatever the version, and the fixture gave the published and draft versions the same name, so resolve reading the draft (no DOI) instead of the published version, or asking for `/dandisets/None/...`, passed. The same burn-down found `(info or {})` turning a version-info 200 of `[]` or `null` into a record with no metadata and no error (fixed; see CHANGELOG). Now: `tests/test_dandi_observed.py` serves info and assets ONLY at the version resolve should read (404 elsewhere), gives the alternatives different values, and pins every request path and param. Not a hook: whether a mock's routing is specific enough depends on which choice the code under test makes.
- 2026-09-30 — A fix closed one call site of a class and left its sibling in the same function open (review of #144): the burn-down added `expect=dict` to DANDI's version-info read after a `[]`/`null` body turned into a metadata-less record, but the dandiset-detail read three lines earlier still took any JSON, so `null` or `[]` was reported as "no such dandiset". Now: the detail read passes `expect=dict`, and `test_a_body_that_is_not_an_object_is_an_outage` covers every DANDI call site. The class is wider than dandi: 37 of 50 `request_json` calls across 27 modules declare no `expect`. Candidate mechanism, not yet done: make `expect` a required argument of `request_json`, so each call site must state the body it accepts.
- 2026-09-30 — A required argument stopped being required one wrapper away (review of #145): `request_json(expect=...)` was made required so mypy would reject any call that omits it, but dandi's and biostudies' `_get_json` forwarded `**kwargs: Any`, so a `_get_json(...)` call without `expect` type-checked cleanly and would fail only at runtime, on a path some test happened to run. Now: both wrappers take `expect` as their own required parameter (mypy, run from inside `src/`, reports `Missing named argument "expect"` for each), and `test_every_request_json_call_names_expect_itself` fails if any `request_json` call anywhere in `src/` gets `expect` by forwarding instead of naming it. A probe file OUTSIDE the package proved nothing: `ignore_missing_imports` typed the import as `Any` and mypy passed the omission.
- 2026-09-30 — A test that reads the source tree failed the mutation run before it tested a single mutant (#88 burn-down of `pdb`, finding in #145): `test_every_request_json_call_names_expect_itself` parses `src/`, and under mutmut `src/` is the rewritten copy, whose generated mutant functions include ones that delete `expect=`, so mutmut's stats pass failed ("1 failed, 505 passed") and left all 15,776 mutants unchecked; the nightly mutation job would have done the same on every run after #145 merged. Now: the scan is in `[tool.mutmut] pytest_add_cli_args`' deselect list beside the other two tests that cannot run under mutmut, with the reason, and it still runs in the normal suite. Check for any new test that opens files under `src/`: run `mutmut run` on one module before merging it.
- 2026-09-30 — A fix for an upstream's in-band error landed in one adapter and not its sibling on the same protocol (#88 burn-down of `pdb`): openneuro already raised on GraphQL's `errors[]` inside a 200, but pdb's `_hydrate` read the same envelope (RCSB's live answer to a rejected query: 200, `errors`, no `data`) as zero entries, so resolve said "no entry" and search returned a hit count with no records. `expect=dict` (#145) could not see it: the envelope is a dict. Now: pdb raises `UpstreamUnavailableError` quoting the messages, and `test_graphql_error_is_an_outage_not_a_missing_entry` fails on the old code. Not yet caught for the class: each GraphQL caller still checks `errors` itself; a shared `_http` GraphQL helper would make a third source unable to forget.
